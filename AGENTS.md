# Portfolio Agent Guidance

This repository is a small, focused public portfolio of selected personal projects, not a complete employment portfolio or a catalog of every school or personal project. Other work can be presented through the CV. Start with the [README](README.md), and use the [project profile authoring skill](.github/skills/project-profile-authoring/SKILL.md) for profile work.

- Keep profiles focused on selected projects or related sets of projects. A profile describes a project, not a repository mapping; one profile may cover a larger repository containing multiple related projects.
- Explain the main techniques used, project-specific lessons, and a sufficiently detailed but sanitized high-level organization. Keep generic technical explanations in authoritative references; this repository is not an IT dictionary, code mirror, or complete project archive.
- Verify details against authorized repository and documentation evidence. Attribute supplied CV claims to the CV and separate them from independently verifiable details; do not infer implementation, organization, status, or outcomes.
- For a private project, publish only an explicitly authorized, public-safe summary. Keep it self-contained, do not link to private repositories or internal evidence, and never imply that private sources are publicly accessible.
- Keep implementation code, secrets, inventories, private configuration, and personal or sensitive data out of this repository.
- Make changes only to this portfolio repository when working here; the project repositories remain the owners of their own content.
